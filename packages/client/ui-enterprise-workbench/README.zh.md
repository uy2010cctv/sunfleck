## 概述

Enterprise digital-employee roster and operations workbench over DSH runtime facts。

侧栏入口与工作台顶部标题使用 Lichen Agent 名称、提供的两片组合 Logo 和内嵌 Tourney 字体。功能导航与说明文案保留数字员工用语。字体遵循随包提供的 [SIL 开源字体许可证](LICENSES/tourney-OFL.txt)。

侧边栏的定时任务快捷入口与 Cordis Plugin 位于同一行，点击后在当前会话上方打开居中的任务弹窗。弹窗复用工作台的定时任务新建、暂停、恢复与归档操作；企业数据已加载时会刷新任务列表。完整工作台仍保留定时任务页。

定时任务表单铺满弹窗内容区，员工选择器每人只显示一个带头像的选项。保存任务时使用所选员工最新的已发布版本；已有任务继续绑定原来记录的发布版本 ID。

员工编辑器按分类列出已绑定能力的名称与修订。已绑定资产仍可选择并明确标注；更新修订会替换旧引用，移除绑定只修改本地草稿，保存并发布后才供新任务使用。分类数量表示绑定数；目录加载中、失败、空分类和全部已绑定分别提示。

提供方自有知识库通过 `enterprise.employee-knowledge-bindings` 槽位进入“知识”分类。提供方按员工 Preset id 保存知识库引用，并把已绑定数量回报给分类卡片；文档不会复制进企业资产目录。对话选择与检索范围继续由知识提供方负责。

员工知识库绑定贡献在查看其他能力分类时仍保持挂载，因此进入编辑器或发布后重新加载时会读取已保存数量。隐藏控件不会暂停其读取生命周期。

员工卡片与能力概览通过既有知识槽位的 `summaryOnly` 请求提供方数量。提供方读取已保存绑定或知识库元数据，无需挂载编辑器；`refreshKey` 在页面刷新时重新读取统计。空值代表正在加载或暂不可用，显示横线；确认结果为空时才显示零。

## 包详情

群聊与频道分别占据左侧栏中 Workspace 旁的标签，即使未选中 Session 也可使用。创建时选择可见的员工发布版本、明确的人类成员和可访问工作区。点击条目后，人类与数字员工在同一条房间时间线中发言。输入框可以明确提及数字员工或人类成员，也可选择线程根消息；没有指定 Bot 的消息仍会留在房间中。发送失败时保留草稿，投递结果不明确时复用请求编号。本地待发送和失败回显不会作为服务端轮询游标；签名接收回执清除临时发送错误。时间线先显示最近的事件，按已授权的事件游标轮询，加载更早消息时保持滚动位置，并显示签名作者与执行来源；线程、表情回应和搜索使用同一事件记录。房间列表携带新消息和提及提醒；分类标签显示提醒点，只有打开并展示对应房间的事件页后才清除。人类和 Agent 发言保留签名作者身份。失去访问权后立即清除房间内容。员工 Session 仍是 Bot 发言所关联的执行记录，工作区浏览和搜索通过持久房间绑定省略这些执行行。

工作台的协作空间分列项目、当前成员可见的群聊与频道。创建项目只需名称和目标；Host 选择受管路径，并为当前成员创建原生项目 Workspace。每条群聊或频道可打开同一个原生时间线；创建操作进入原生房间表单，从进行中的项目详情创建时预选项目关系。已归档项目的会话仍可读取，但不提供新建关联会话操作。项目详情读取持久化成员名册，只展示关联到该项目的群聊和频道。团队治理仍是管理章程、运行和人工决策的页面，并可返回协作空间。目录不声称向非房间成员的管理员展示全组织房间清单。

房间右侧区域展示已授权成员、关联项目和章程资料，或选中的线程。原生执行 Session 的详情继续使用现有右侧栏标签。员工、项目上下文和已批准记忆通过会话级端点读取，导航或重连时清除旧数据；隔间过滤仅显示已授权返回的摘要。此视图不提供记忆审批或修改操作。

频道详情读取已保存的分版本 YAML 工作流。Host 按当前策略返回是否可管理；其他成员只能查看定义。管理员为工作流命名，并以最近读取的版本号显式保存 YAML。保存失败或版本冲突会保留草稿；读取当前版本后仍可对照草稿。编辑器列出支持的触发条件与动作字段，执行结果继续记录为频道事件，审批决定仍由企业审批服务负责。

同一频道区域读取待审批决策并展示真实摘要。只有服务端明确返回决策权限时才显示“批准”和“驳回”。提交携带最近读取的版本号和稳定的重试键。结果不确定时可用同一键重试；版本冲突需要刷新后再次明确选择。提交成功后，界面等待待审列表确认该项已移除，才提示已记录。权限被撤销时隐藏操作，保留待审卡片及恢复提示。

DSH Web 的企业数字员工运营界面。企业 Profile 通过强类型 Host API 读取经过身份校验的 PostgreSQL catalog 与 operations 投影；普通 Profile 只在企业域明确返回 unavailable 时保留原生运行时投影：

- 新 Session 将 Agent Preset 工作方式与一份已发布数字员工版本组合使用；旧员工 preset 声明保留供历史 Session 回放。
- Workspace 是业务空间。
- Session 是工作记录。
- 待处理交互、运行状态、完成提示、Jobs 和 Session 投影继续由原有包负责。

浏览器插件向 `sidebar.footer.action` 增加入口，向 `shell.overlay` 增加运营台；不会替换 Sidebar 或 Conversation。企业治理继续属于 Settings。Overlay 内部管理数字员工、工作记录、审批、定时任务、能力资产和团队；桌面使用导航侧栏，窄屏使用容器内横向导航，页面本身不产生横向滚动。

Controller 调用 `enterpriseEmployees`、`enterpriseAssets`、`enterpriseTeams` 和 `enterpriseOperations`，不接受也不发送组织或 principal，身份由 Host 注入。员工搜索、发布状态、可见性和负责人筛选均在服务端执行，并使用 cursor 分页。员工编辑为显式保存草稿，由 `expectedRevision` 保护；冲突时保留未保存输入。发布、版本历史、回滚、工作状态、审批决策、调度生命周期、资产版本和固定团队都使用真实强类型 mutation。

Workspace 扩展页默认在“我的扩展”汇总调用者可见的所有工作区。每个 Plugin 及作用范围只显示一项，不可变版本放在选择器内；生效绑定、来源工作区和可执行动作各显示一次。工作区选择器可缩小列表；一个工作区读取失败时，其余记录仍可管理。所有者可启用所选版本、提交部门工作区内的私有版本审核、将私有 Plugin 移入回收站，并在恢复后自行决定是否重新启用。已提交的版本显示审核状态，不再提供重复送审。审核页按 Plugin 和部门合并请求，最新请求直接显示，较早决定放在可展开历史中。部门与组织动作只在有权限且绑定状态允许时出现。版本和使用范围的变更只影响新 Session；会话 Cordis 面板单独显示进程内正在运行的 Plugin。

员工页默认显示员工名册：搜索、发布状态标签和员工卡片。工作区选择用于卡片发起的新对话；默认员工设置和高级筛选分别在页内展开。次要入口“按目标派工”展开工作面板，收起时保留已填目标。员工编辑页隐藏这些名册控件。它把目标、可选截止时间，以及仅在确有打开的原生 Session 时才存在的该 Session 发送给 `enterpriseWork.prepare`；不会按列表顺序猜测工作区。就绪结果以一次浏览器生成的幂等键启动工作，打开返回的原生 Session 并关闭 Overlay。存在歧义时只从已加载的浏览器快照中展示匹配的 Workspace 名称，或数字员工姓名与发布版本；标识符、模型路由与团队设置不会出现。准备或启动失败保持可见，并提供重试和清除操作。

员工页还要求在员工卡片启动前选定工作区。部门经理或组织管理员可设置该工作区的默认员工；个人工作区由所有者设置。其他成员只看到有权使用的员工。新会话先展示工作方式选择器，再展示员工选择器；可用的工作区默认员工只会预选员工，不会发送任务消息。成员在首轮对话前可分别切换工作方式与员工。员工选择器显示该 Session 实际记录的发布版本，即使员工后来发布了新版也不会误报。旧员工私聊目录在完整的 PostgreSQL 运行时可用前从界面隐藏，其存储数据和接口保留。

企业 Host frame 由 runtime 的唯一流消费者转发。每个企业 frame 都携带 `resourceType`；工作台按 `eventId` 去重，即使归属页在后台也会刷新对应 read model。所有 mutation 共用可控的错误/重试状态，重试复用首次生成的 idempotency key。Revision conflict 绝不使用旧 revision 重试：恢复操作只重新加载服务器版本，员工编辑保留本地未保存副本并显示差异。运营人员随后明确采用服务器草稿，或在新服务器 revision 上保留本地字段。如果重载失败，重试只重复该重载。各页失败保持独立：loading、empty、error、forbidden 和部分成功不会清除已成功读取的模型。

员工展示信息来自已发布的目录版本，包括姓名、岗位、部门、能力标签和不可变版本号。这些字段用于描述员工；能力标签不会授予工具或权限。员工的 preset id 仍是稳定的运行时身份。

群聊与频道输入框复用工作区聊天的外壳、工具栏和发送按钮，保留附件上传与成员提及，不展示模型或权限选择器。添加按钮打开工作区候选菜单中的文件操作，选择后打开文件选择器。选择、粘贴和拖拽的文件进入同一房间上传流程。草稿使用工作区附件栏和图片灯箱；每个可见输入框独立管理拖拽区域。等待或失败的上传阻止发送，移除附件时释放图片预览 URL。签名记录中的永久附件错误显示在源消息旁，不进入折叠的执行详情；章程附件交付不可用时保留草稿并显示明确提示。交付文件卡片使用现有交付物工厂。预览按生成文件的 Session 打开，并保留房间界面。签名回复更新时刷新文件元数据；完整日志中的原生结束位置将已登记文件关联到产生它的回复，覆盖分页和线程历史。

频道采用左对齐的帖子列表和独立线程面板。回复数量只统计签名文本帖子，执行记录折叠到所属员工回复中。房间或线程中定向发给数字员工的人类帖子，都会显示同一套员工头像和「正在回复」状态，直到该员工在同一会话范围内提交签名回复。持久化话题目标将历史上未标线程的员工记录归入其已知线程，不修改签名事件。线程页读取已授权原帖，即使它不在当前房间页中；较窄的房间容器以单面板显示线程，关闭后键盘焦点返回发起控件。

群聊与频道详情共用基本信息和成员布局。管理员编辑及可添加成员搜索走受保护的房间接口；其他成员可确认离开。移除和解散确认在失败时保留输入。当值设置仅使用当前数字员工，工作流与审批位于独立折叠区。解散后历史记录仍保存在存储中。

团队治理以章程列表为入口。创建时分组展示团队目标、成员与分工、验收与权限，并明确列出尚未满足的启用条件。已保存草稿显示存储版本；未选定或没有已启用章程时不显示可编辑的启动字段。兼容固定团队默认折叠，并排除受治理团队的兼容投影。草稿保存和启用的重试保留原幂等键，避免已提交但响应丢失的写入被当作新命令再次提交。

工具分类从已授权的原生 Session 目录选择来源，并调用 `session.capabilities`。已有 Agent 时显示其作用域内的注册工具，否则显示最近记录的目录及原生/PTC 调用尝试，不启动 Agent。工具类型、精确 MCP 身份、已配置的 ACP 集成、可用状态和使用情况分别展示；注册不代表连接健康，旧日志可能没有集成来源。切换来源取消旧读取并忽略迟到结果；读取失败清除旧元数据并提供重试。运行清单与自建工具资产分开，不自动创建重复资产记录。

## 普通 Profile fallback

只有 `enterpriseEmployee.list` 返回明确的 enterprise-unavailable 应答时才进入 fallback。其他传输、授权、cursor 或服务端错误保持可见。fallback 名册只包含标记为员工的声明；通用工作方式仍在工作方式选择器中。启动 fallback 员工时必须明确选择工作区。

## 安全边界

本界面不负责用户认证或工作记录授权；它消费 Host 已按身份与权限过滤的 read model，mutation payload 中不发送 `orgId` 或 `principal`。单企业内网多用户部署仍必须组合企业 Host 身份与授权服务。loopback/trusted-host 只是传输边界，不是身份认证。

## Model Experience

### 浏览器运营投影

#### What the model sees

无。该工作台只投影浏览器状态并调用 `SessionRuntime.create`；不增加 Prompt 分区、模型 Tool、Message、Session Event 或模型调用。

#### Token effect

无。启动员工会创建原生 Session，之后的 Conversation 请求自行承担常规 Token 成本。

#### KV Cache effect

无。打开工作台不组装或修改提供方请求。

## Known Limitations and Deferred Work

- 企业 UI 只展示 catalog 和 operations read model 中存在的字段，不推断生产力、SLA、完成百分比或业务结果。
- 草稿 profile 是开放 JSON 上的强类型 UI 投影；本编辑器只写回它支持的 profile 字段。
- 能力绑定和团队成员使用已加载的资产与发布版本选择器；原始 ID/JSON 只在高级编辑中保留，用于尚未结构化的策略细节。
- 身份认证、角色分配、凭据、模型管理和组织治理仍属于 Settings。
