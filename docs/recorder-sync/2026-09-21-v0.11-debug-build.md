# 录音卡片 v0.11 调试构建记录

时间：2026-09-21。

本轮目标是生成可安装的 Android 调试 APK，并验证此前录音卡可靠性改动进入构建产物。

已纳入本轮构建的录音卡改动：

- 段级 SQLite 队列保存稳定段 ID、设备与录音会话归属；服务启动与 WorkManager 网络恢复会尝试补传积压。
- 暂停、恢复和 BLE 断开会收尾当前 VAD 段，并在恢复后重新锚定墙钟，避免把停顿压缩到时间线。
- WAV 每秒刷新数据后才修补头部，避免头部声明的数据长度超过落盘内容。
- 上传请求携带稳定段 ID；ASR 返回句级说话人聚类标签。标签不是本人身份，未知归因保持未知。
- SDK 文件数据回调已接到回补解码通道；自动删除仍关闭，低容量仅告警，等待逐文件的归档、入库和读回证明。
- 主界面改为暖白、墨绿的林下光状态面板，显示设备状态、待同步段数和已转写段数；版本号为 0.11.0。

构建、安装、真机录音、锁屏、重启、断网恢复和卡片删除验证结果将在本文件后续追加。未通过这些验证前，不把 APK 视为生产发布版本。

## 构建记录

- 首次 Gradle 构建发现 `RecorderService` 调用了但未实现 `flushVadToQueue`，导致 debug 与 release Kotlin 编译失败。
- 已补齐该方法：暂停、断开和重新锚定前会把可用语音段按当前设备与会话写入 SQLite 队列，并立即唤醒上传器。
- 修复后需重新执行完整 `test assembleDebug`，以确认 APK 产物包含修复。
