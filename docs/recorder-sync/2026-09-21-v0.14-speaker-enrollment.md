# 录音卡 v0.14 本人声音登记与 CAM++ 归因记录

时间：2026-09-21。

## 根因

线上 ASR `/health` 返回 `speaker_model: null`。源码虽支持 `ASR_SPK_MODEL=cam++`，实际进程由终端手工启动，未安装 ASR launchd 服务，因此新段的 `speaker` 一直是 `unknown`/`null`。`speaker_profile.py` 只有余弦匹配函数，没有持久化、登记端点或实际调用路径。

## 实现

- FunASR 主模型启用 `spk_model=cam++`，保留句级 `spk_0` / `spk_1` 聚类标签。
- 独立使用 `iic/speech_campplus_sv_zh-cn_16k-common` 生成本人声纹 embedding，不把聚类编号当作身份。
- 增加 token 保护的 `/v1/speaker/enroll` 和 `/v1/speaker/delete`；登记需要 20–90 秒 PCM16 单人音频。
- 47 网关从已鉴权 token 解析组织和用户，生成稳定不透明 profile id；手机传入的 profile id 会被覆盖。
- 声纹文件保存在 0700 私有目录，文件为 0600，名称只含 owner id 摘要。
- 单人段与本人 profile 余弦相似度达到 0.72 时返回 `self`，否则返回 `unknown`，同时保留 `speaker_cluster` 和 `speaker_score` 供诊断。
- Android v0.14 增加“登记 / 重试本人声音”：开始录音后收集恰好 30 秒 PCM，显示进度，网络失败时保留在 App 私有文件中供重试。
- ASR 改为 launchd 常驻，只监听 `127.0.0.1:8765`，由 SSH 反向隧道供 47 调用。

## 实机待验收

外地手机需安装 v0.14，开始录音后由本人在安静环境连续说话 30 秒完成登记。登记后需分别录制本人、其他人和重叠语音，统计本人精确率、召回率与 `unknown` 比例。没有这组真实证据前，不宣称达到 99% / 90% 目标。

## 远程实机故障与修复

用户首次在外地手机执行 30 秒登记时，App 返回 `401 invalid or missing token`，普通转写同时返回 502，SQLite 队列积压 814 段。根因是部署时在 47 `gateway.env` 写入了错误变量名 `RECORDER_ASR_TOKEN`，而网关源码读取 `ASR_AUTH_TOKEN`，导致 47 仍用旧 token 调用已轮换 token 的 Mac ASR。

修复后：

- 47 只保留正确的 `ASR_AUTH_TOKEN`，环境文件以 0600 权限原子替换，旧文件已备份。
- 47 通过 SSH 隧道访问 Mac `/metrics` 已返回 HTTP 200。
- 重启网关后，段账本从 1289 增长到 1385，用户分区转写文件在 4 秒内持续更新，证明积压已自动恢复上传。
- 新的非空转写已返回 `speaker: spk_0`，证明 CAM++ 聚类标签进入真实链路。
- App 将登记 PCM 保存在私有文件中；用户点击一次“登记 / 重试本人声音”即可复用已录制的 30 秒样本，无需重新录制。
