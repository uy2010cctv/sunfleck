# 企业协作版本文档 — 2026-09-27

[English](2026-09-27-enterprise-collaboration-release.md) | 中文

> 版本范围：群管理员、房间消息对齐、壳层调整，以及随之落地的修复。全部改动已合并至 `master`，区间为 `4e1a448adc` 至 `4ef40dc514`。

## 群管理员

创建群聊的成员即该群的记录管理员，也是唯一可以重命名群、替换或清除群公告、添加和移除人员与员工成员的成员。管理能力走新增的认证路由（`rename`、`announcement`、`members/add`、`members/remove`），房间详情返回 `viewerIsAdmin` 及可选的 `adminUserId` 与 `announcement`，侧栏房间详情面板只为管理员渲染编辑入口。新加入人员必须保持工作区访问权限，新加入员工必须解析为可见的已发布预设，管理员本人永远不会被移除。本版本之前创建的群不暴露管理入口。

## 房间消息对齐

本人的发言在群聊、频道和线程中右对齐；数字员工在所有出现身份的位置渲染其已发布的 dicebear 头像：房间消息、会话头部入口、新会话员工选择器、提及菜单。头像种子的解析与名册卡片一致——档案种子优先，否则用员工 ID。房间发送框获得了工作区发送框的附件能力，但不带其 Session 专属控件——没有模型选择、没有权限选择：文件以原始字节上传到房间专属路由（单文件 20 MB、每条消息最多 8 个），先于引用它的消息提交，以签名的 `attachment` tag 记录，按成员范围下载，员工提示词会列出文件名。输入 `@` 唤起按已输入片段过滤的成员选择器并插入所选显示名；选择器行携带名册头像。存储契约从「仅文本」改为「支持附件」，并通过一次幂等的启动迁移新增附件表。

## 壳层调整

「插件」入口从顶部面板列表移到新的 `settings.aux` 触发行槽位，位于侧栏底部的设置启动器旁（窄栏下纵向堆叠）。轮次过程运行标签将「深度求索中」替换为生长循环标记——种子、萌芽、破土、成树、繁茂、盛放——每 3 秒循环一次，旁配柠檬绿（`#32cd32`）的「智能生长中」，文字上有一道流光划过；减弱动效时固定显示「木」字形。

## 修复

`replayedTargets` 曾把刚创建的工作 Session 当作错误，因为该 Session 还没有持久化事件，导致首次提及某员工时消息已提交却整体失败；现在空历史即重放基线。房间附件表改在模式版本短路之前创建，已迁移的数据库在首次启动即收敛。`serveRoute` 在把路由错误折叠为 400 之前先记录日志，不再静默吞掉。

## 运维说明

本地企业部署以 `pnpm run dev:web --skip-build --patch apps/cli/config/enterprise.cordis.patch.yml` 启动，环境文件为 `~/.dsh/enterprise/local-dev.env`（主密钥、引导密码、数据库地址、组织 ID）。房间签名密钥绑定成员的首个公钥：轮换企业主密钥会使既有绑定无法签名，恢复方式是删除 `dsh_enterprise_collaboration_actor_keys` 中受影响行，让成员在下一条消息时重新绑定。历史签名事件保持有效。
