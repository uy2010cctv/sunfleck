# Enterprise memory consolidation runtime

English | [中文](2026-09-23-enterprise-memory-consolidation-runtime.zh.md)

Consolidation planning and LLM refinement landed as pure modules; they had no caller that wrote anything back. The runtime now owns the interval lifecycle, the per-compartment pass order, and the manual trigger, and it is the first consumer that turns the supersede, decay-batch, and reflection primitives into store writes.

The interval runs only for organizations listed in `consolidationOrgIds` (default empty, so the interval is inert by default) every `consolidationIntervalMs` (default 6 hours; `0` disables). The store does expose `listOrganizations`, but defaulting to "every org" would start unconfigured model calls org-wide on first launch, so listing orgs is the honest opt-in; an enabled interval additionally requires the `service:` consolidation actor and a provider/model route, all validated loud at plugin load. The manual endpoint `POST /enterprise/consolidation/run` works per org regardless and answers 409 through the same in-process per-compartment guard the interval skips on, so enabling the interval on more than one host is unsafe by construction.

Digest supersede follows from the store's own rules. `supersedeMemory` refuses non-approved rows, so a digest left `proposed` would block every future digest forever; consolidation therefore activates its own digest immediately after the scope-aware privacy gate passes and supersedes the previous approved digest, keeping a deterministic digest-id chain. A regenerated digest identical to the live one reports `unchanged` and writes nothing. Project compartments defer their digest in P3 while the structure pass still runs.

Pure retirement has no dedicated store API — `supersedeMemory` requires a replacement row — so decayed entries retire through the review CAS path with the consolidation actor as reviewer; a stale revision is a recorded failure the next run retries. Department-target reflections stay failed-with-reason in P3 because agent notes carry an employee id and no mounted service resolves a writer's department.

Decay and retirement share one clock, and the runtime spends it on retirement: the importance batch never writes `lastAccessAt`, so consecutive runs re-apply the full anchor-age factor to the already-decayed value and an untouched entry compounds below the half-life curve until retirement (which additionally requires access-clock staleness) fires. Writing the clock alongside the weight would give the exact half-life trajectory but reset `retirePlan`'s staleness on every run and disable retirement outright; recall stays the only clock writer. An unmounted `llm` service marks the reflection pass `skippedLlm` the way the digest reports `skipped-llm`, and regenerating a rejected digest's identical text re-proposes its deterministic id and fails loud on the store's id conflict rather than masquerading as `unchanged`.

Validation includes real-store runtime tests over the SQLite identity repository (supersede, decay, retire, digest written/unchanged/privacy-skip/llm-skip, reflection propose/drop/fail, reentrancy, interval lifecycle, config boundaries), controller endpoint tests for 200/401/403/400/409/503, and the repository-wide typecheck.

Task 4 closes the write side and the archival loop. The store's direct-write path widened from the two private compartments to include the member-gated `project` compartment: `writePrivateMemory` now requires exactly a `projectId` for project scope, the shared privacy policy blocks every finding there (matching organization and department), and the dedupe predicate covers the new scope so both stores converge repeats on `private-memory-<digest>`. Project-scope knowledge therefore reaches an active project as an approved row without review, which is the L3 semantics — membership is the review — while content keeps the same hard gates as shared memory. `memory_write` accepts `scope: "project"`, `memory_search` and `memory_read` expose the compartment to member sessions, and every failed write gate is a structured tool error because a write must never silently no-op the way a read resolves to nothing.

Announcement intake gained the D5 extraction seam as a cross-package dependency: enterprise-surface → enterprise-memory-context (no cycle, memory-context imports nothing from enterprise-surface). The shared `extractAnnouncementMemories` helper in memory-context owns the strict-JSON one-shot call and the per-candidate scope classification, returning `undefined` for any failure so the channel can fall back to the exact pre-extraction truncated proposal; an empty candidate list is a valid "nothing durable" result, not a failure. The channel owns proposal writes with deterministic `announcement-memory-<digest>` ids (a repeated announcement converges on its rows instead of piling up), and the `ChannelIngestedDelivery` result switched from one `proposedMemoryId` to `proposedMemoryIds` plus `droppedPrivacy` because a batch with drops is a delivered result, not a `privacy-gated` failure. Extraction stays off until both config fields name a provider/model route, validated loud at load when only one is set.

Project distillation (D6) lives in a dependency-free module taking resolved stores, model surface, clock, and an audit callback, so the runtime keeps one service surface: `ctx.memoryConsolidation.distillProject`. Lessons propose with `project-distill-<sha256([projectId, summary])>` ids, making re-runs skip what already stands instead of conflicting, and the runtime audits every run — including structured skips and a best-effort record of thrown failures, because the post-archive trigger swallows rejections. The controller mounts the seam as the runtime service itself (branch-free composition wiring): the manual route gates on membership and folds existence behind 404, and the archive route fires distillation without awaiting it — the archive is committed first, so memory work must never block or fail it.
