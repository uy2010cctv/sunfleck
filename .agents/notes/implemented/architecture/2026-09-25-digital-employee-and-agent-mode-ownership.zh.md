# Agent Note: 数字员工与 Agent 工作方式的归属

Status: implemented

[English](2026-09-25-digital-employee-and-agent-mode-ownership.md) | 中文

## 问题

企业目录把员工身份发布为 Agent Preset 声明，以便 Session 运行。若把这些声明当作普通自定义模式展示，同一员工会出现两个管理入口，还可能被设成对无权使用该员工的用户生效的全局新任务默认值。

## 决策

目录草稿和不可变 Release 负责员工身份、权限、职责与版本。Agent Preset 注册表负责可执行组成，并把目录投影标为 `kind: employee`；普通声明是工作方式。设置页只允许工作方式成为全局默认值。企业选择器只列出有权限的已发布员工，并报告 Agent 保留代际实际挂载的发布版本。

工作区可保存一个员工身份作为默认值。所有者或获授权的负责人通过 revision 校验修改它。仅当员工仍已发布且对成员可见时，成员才会看到该选择；否则新会话显示标准模式并说明回退。成员可改选，预选不会发送任务消息。Host 在更改空白 Session 并记录实际挂载版本前，重新校验 Session 所有者、工作区授权与员工目录权限。

旧员工私聊目录保留源码和数据，但在其 PostgreSQL 运行时能提供完整流程前从工作台隐藏。既有 Session 标识和历史不会被改写。

## 考虑过的替代方案

**继续把员工放在自定义模式分组。** 不采用，因为运行时声明不负责员工发布或授权，且全局默认值可能在不同用户与组织中失效。

**强制使用工作区默认员工。** 不采用，因为成员处理其他任务时需要改选有权限的员工或通用工作方式。

## 影响

- 工作区负责共享的员工预选；目录仍是员工发布版本和可见性的权威。
- 通用 preset 保持可复用，而不会成为企业员工。
- Session 记录员工 preset id，工作记录保存选择时使用的不可变发布版本。进程重启后的 Session 回放仍遵循注册表的当前定义规则，不会从 Release 快照重建已退役的代码代际。
