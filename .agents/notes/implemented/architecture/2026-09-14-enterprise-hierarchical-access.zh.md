# Agent Note: 企业层级控制员工资源

Status: implemented

[English](2026-09-14-enterprise-hierarchical-access.md) | 中文

## 问题

渠道、企业记忆和数字员工过去分别组合使用组织角色、负责人 id、工作区路径和可见性字段。渠道后台 Session 还可能没有经过认证的人类主体。这些差异会让调用方看到不属于其部门的目录资源，也会诱使后台执行借用人类身份。

## 决策

`enterprise-governance` 统一拥有组织、部门、员工和个人四级范围。认证会把人员的部门归属投影到主体，并从企业目录解析其负责部门。授权服务先判断层级，再判断资源可见性，并为部门成员、部门经理、员工服务执行、个人所有权和范围不匹配给出稳定原因。

员工定义通过负责人的权威部门归属确定范围。绑定到不可变员工发布版本的渠道，会沿发布版本和员工定义解析到同一个部门。目录控制器在返回每条员工和渠道记录前应用解析后的权限决定。

后台执行使用 `employeeServicePrincipal`。该主体只命名一个不可变员工发布版本，不具有人类角色或负责部门，只能执行命名同一发布版本的资源。工作目录、最近登录的浏览器用户或显示名称都不能建立后台权限。

## 验证

治理测试覆盖跨组织拒绝、部门成员、部门经理范围、个人所有权和精确员工发布版本执行。认证测试覆盖部门投影和负责部门判断。插件与控制器测试覆盖员工和渠道的层级解析及列表过滤。

## 考虑过的替代方案

**保留各资源独立的权限检查。** 角色或组织归属变化后，分散检查容易产生漂移，也无法输出统一的审计原因。

**把工作区路径当作身份。** 路径只标识存储位置，不能证明由哪个员工发布版本或人员主体执行；发布目录路径也不属于受管企业工作区注册表。

**让渠道以员工负责人身份运行。** 这种方式会把人类拥有的全部权限交给后台传输，并把自主工作错误归因到人员。

## 后果

渠道、记忆和数字员工共用同一套授权词汇和审计路径。人员调岗后，后续权限直接遵循组织目录，而不是复制的显示文本。渠道适配器必须为员工范围执行提供精确的员工发布版本；尚未绑定员工的渠道配置仍由组织管理员管理。
