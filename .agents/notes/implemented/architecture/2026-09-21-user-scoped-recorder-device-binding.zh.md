# Agent Note: 用户级录音卡设备绑定

Status: implemented

[English](2026-09-21-user-scoped-recorder-device-binding.md) | 中文

## Problem

Device Plane 通过 Ed25519 公钥把电脑配对到已认证的组织用户；录音网关则通过 APK 内置 token 和人工维护的序列号白名单映射用户。后一条路径无法支持用户自助绑定、设备转移、撤销或“我的设备”统一展示，也不能把录音卡误当成 Computer Use 执行设备。

## Decision

企业控制面把电脑和录音卡统一展示为用户所有的设备，同时保留不同的认证记录和能力范围。当前用户在“我的设备”生成一次性录音卡绑定挑战；Android 中继提交该挑战、录音卡序列号和中继公钥。服务端从挑战解析所有者，不信任 App 提交的 userId。

## Device records and authentication

电脑记录继续归 Computer Use Device Plane 所有，并继续使用 Ed25519 公钥验证 Agent 请求。录音卡记录应保存组织 id、用户 id、显示名称、服务端 HMAC 处理后的录音卡序列号、Android 中继公钥、状态、最后在线时间和时间戳。录音卡只获得音频上传和状态上报能力；Computer Use Run 和 Permit API 必须拒绝录音卡。

Android 中继在 Android Keystore 中生成密钥。录音卡绑定挑战在十分钟后过期，只能消费一次，并受网关限流保护。同一用户重复绑定同一录音卡时返回已有记录。另一个用户绑定仍处于启用状态的录音卡时失败，直到后续实现撤销或转移流程。

当前绑定响应会签发一个随机录音卡凭据，网关注册表只保存其摘要。每次上传携带该凭据和录音卡序列号；网关解析持久化的组织和用户映射，并将它写入转写归属。中继公钥为后续签名请求升级保留，本版未实现上传签名和 nonce 重放保护。APK 不包含共享的生产网关 token。

## User experience

工作台的页面和导航应统一使用“我的设备”。页面保留电脑的“连接此电脑”，并增加独立的“绑定录音卡”。设备行展示易懂名称、设备类型、在线状态、最后在线时间和对应类型的测试。普通界面只显示录音卡序列号末尾掩码，不暴露公钥、内部 id、签名或绑定密钥。

## Migration

只有在组织、用户、token 和序列号关系明确时，才导入现有录音网关 JSON 注册记录。导入的绑定应标记为迁移记录，并在移除共享 token 兼容路径前完成中继公钥升级。无法确认的记录应隔离等待处理，不能分配给第一个用户。

## Alternatives considered

**把录音卡写入现有电脑表。** 这需要伪造公钥或引入可空字段，并且可能让 Computer Use 在每个调用点都增加设备类型检查。独立认证记录加统一用户展示可以保留现有 Computer Use 不变量。

**继续使用 JSON 白名单。** 该方案操作简单，但要求管理员修改，缺少认证用户的自助绑定流程，也无法安全表达撤销和转移。

**信任 Android App 提交的用户 id。** 这会允许设备选择其他所有者。组织和用户范围必须由服务端的一次性挑战确定。

## Verification

- 已认证用户无需管理员即可绑定录音卡，其他用户不能消费或重放该挑战。
- 同一用户和录音卡重复绑定保持幂等；其他用户在明确转移前收到冲突。
- 录音上传只通过持久绑定和服务端签发的专属凭据解析用户归属。
- Computer Use 在创建 Run 或 Permit 前拒绝录音卡设备。
- “我的设备”只列出当前认证用户的电脑和录音卡，显示类型对应的操作且不暴露秘密标识。
- 迁移的录音卡在过渡期可以上传，录音卡获得专属凭据后可移除旧的共享 token 记录。

## Consequences

当前录音卡不能签名，因此 Android 手机成为录音卡的认证中继。手机丢失后必须撤销凭据并重新登记；本版会记录中继公钥，但尚未提供撤销或转移控件。短绑定码在有效期内可能被诱骗获取，因此服务端把它绑定到一个用户，并由网关限制尝试速率。
