# Agent Note: 企业目录管理查询

Status: implemented

[English](2026-08-27-enterprise-catalog-management-queries.md) | 中文

## 问题

企业目录已持久化数字员工草稿和版本化资产，但管理消费方不知道每个标识符时无法发现这些记录。不限定组织的列表或资产版本读取会暴露跨组织记录，而偏移量分页会在操作员更新目录时重复或遗漏记录。

资产移除还需要可恢复的操作，并阻止持有过期 revision 的管理员或被重用的幂等键执行不同请求。

## 决策

`EnterpriseCatalogRepository` 提供组织范围内的草稿和资产列表操作。草稿支持状态、所有者、可见性过滤，以及对 Preset ID 和 profile JSON 的字面量不区分大小写搜索。资产支持种类、归档状态过滤，以及对资产 ID 和名称的字面量不区分大小写搜索。上限默认为 50，只接受 1 到 100 的整数。

列表先按 `updated_at DESC` 排序，再按资源 ID 降序排序。每页多请求一条记录，只在存在下一条时返回不透明游标。游标记录最后的排序元组，以及组织、资源类型和全部过滤条件的摘要。HMAC-SHA256 对其确切的版本、范围、时间戳和 ID Payload 签名；验证先要求每个 Base64URL Segment 解码后必须重新编码为完全相同的字符串，再通过 `timingSafeEqual` 比较等长签名，因此 Padding Bit 变更、Payload 篡改、过滤条件变更和不同密钥都会失败。生产环境提供至少 32 字节且包含至少 8 个不同字节值的稳定密钥，并使用域标签 `dsh-enterprise-catalog/cursor-signing/v1` 从企业主密钥派生。未配置密钥的仓库仅在不存在续页时保留首页兼容性，并拒绝生成或消费游标。

`getAsset` 在参数化查询中同时限定组织。`listAssetVersions` 先执行该归属查询；资产不属于请求组织时，在读取版本行前失败。列表谓词和搜索值都作为 PostgreSQL 参数，不允许调用方提供 SQL 片段。

Schema 版本四保留每个列表的更新时间和 ID 排序所用的组织优先 B-tree 索引，并安装 `pg_trgm`。GIN `gin_trgm_ops` 表达式索引与草稿 Preset ID、草稿 profile JSON 文本、资产 ID 和资产名称的小写 `%term%` 查询表达式完全一致。迁移会删除被替代的小写 B-tree 搜索索引，其 Operator Class 无法加速带前导通配符的匹配。

`archiveAsset` 设置 `archived`、递增资产 revision，并保留全部版本。它使用既有的按资产咨询锁串行化，验证预期 revision，并通过 revision 比较交换更新。幂等记录在结果旁保存组织、资产和预期 revision 的摘要。完全相同的重试在资产已归档时仍返回原始结果；同一键搭配不同请求字段时失败。

## 备选方案

**偏移量分页。** 已拒绝，因为并发保存可以使记录跨越偏移量，导致重复或遗漏。排序元组在不保留服务器列表状态的情况下提供确定性续页。

**仅使用全局唯一资产 ID 限定资产版本读取。** 已拒绝，因为即使标识符全局唯一，组织归属仍是授权不变量。仓库在读取版本前证明归属。

**物理删除。** 已拒绝，因为已发布数字员工版本会锁定不可变资产版本，而管理员需要保留审计的可恢复性。逻辑归档使资产不再可供活动选择，但不破坏历史。

**仅结果幂等。** 已对归档写入拒绝，因为客户端可以用不同的预期 revision 重用同一键，并收到它未发出请求的结果。请求摘要使该冲突变得明确。

**未签名的 Base64 游标。** 已拒绝，因为调用方可以修改最后的排序元组或查询摘要，从而引导下一次查询。稳定的带密钥 MAC 在检测变更的同时保留无状态分页。

## 后果

管理消费方可以分页和过滤目录记录，而无需增加另一个投影存储。每次读取都携带组织 ID，跨组织单点或版本访问会返回无记录，或在版本读取前失败。

游标分页反映每次请求时的有序状态，而非数据库快照，因此在两页之间更新的项可能移到游标之前。密钥轮换会使未完成的游标失效。归档写入的完全相同重试保持稳定；对已归档资产的新归档尝试会失败，除非它是已记录的重试。

## 测试

内存 PostgreSQL 仓库测试固定过滤组合、边界、跨仓库实例的稳定续页、规范 Base64URL 执行、篡改和错误密钥拒绝、未配置密钥时的兼容性、参数化搜索、组织隔离、版本归属、revision 冲突和归档幂等冲突。生产组合测试在打开连接池之前拒绝过短和低多样性密钥。设置 `DSH_TEST_POSTGRES_URL` 时，真实 PostgreSQL 套件会针对同一管理路径、GIN 索引定义和四个搜索表达式的 EXPLAIN 使用、SQL 排序、JSONB、事务和从版本一进行的 Schema 迁移进行固；CI 要求该变量。
