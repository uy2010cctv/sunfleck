# Agent Note: 员工记忆整理与项目结项蒸馏

Status: implemented

[English](2026-09-27-employee-memory-p3.md) | 中文

## 问题

企业记忆只进不出。每条已批准的记忆永远停留在初始重要度：重复条目无人处理，冲突无人解决，没有任何东西衰减，隔间也从不为自己产出摘要。项目结项时教训直接丢失——项目隔间只对成员可读，其他什么都不是，项目积累的经验在归档时蒸发，而不是反哺组织。公告接收把截断的公告原文直接塞进审查队列，管理员只能亲手做抽取。

## 决策

整理是对已批准记忆的按分区处理，由宿主级定时器（`consolidationIntervalMs`，`0` 关闭）加管理员触发端点 `POST /enterprise/consolidation/run` 驱动。结构阶段把重复组接替到最新成员上，把其余条目的重要度用一个批次改写为衰减值，并停用宽限期后衰减到阈值以下的条目。

冲突用接替链解决，而不是原地改写：被接替的行转为 `retired` 并以 `invalidated_by` 指向接替者，历史可以回放，已批准的内容永远不会被原地编辑。衰减批次刻意不前移锚点时钟——既未被召回也未被触碰的条目每次运行都重新叠加完整的锚点龄期，以快于半衰曲线的速度复合衰减直至停用。这个复合是有意设计，不是缺陷：一个时钟（`lastAccessAt`）同时服务衰减与停用的陈旧判定，陈旧判定必须优先，而每次运行前移锚点会每轮重置陈旧判定、彻底废掉停用。召回才是同时重置时钟与衰减的机制，服务于仍在使用的记忆。

每个共享分区保留一条在生摘要：由精炼模型从存活条目写出的 `kind: 'summary'` 行。摘要在任何持久化之前先过分区感知隐私分类，并立即生效——整理是 `summary` 行的权威写入方——同时接替上一条摘要。L4 反思把仍有足够重要度的已批准 agent 笔记提炼为进入普通人审队列的 `business-fact` 提案；被隐私拦截的反思直接丢弃。项目归档闭环：`distillProject` 把项目已批准分区蒸馏为至多五条组织范围的经验提案，逐条隐私分类、逐条等待管理员评审——归档响应从不等待蒸馏。公告接收用同一 strict-JSON 契约经精炼模型抽取可沉淀知识，模型不可用或失败时精确回落到 P3 之前的截断提案。`memory_write` 的 project 范围把成员教训以已启用状态直写项目分区，适用与共享分区相同的隐私策略——成员资格就是评审。

## Alternatives considered

**原地合并重复条目。** 改写存活行并删除其余行更省事，但它抹去哪条先说、由谁先说，而且等于在没有人的情况下编辑已批准行。接替链让审计轨迹可回放。

**每次运行前移衰减锚点。** 连衰减权重一起写 `lastAccessAt` 会得到精确的半衰轨迹，但它每轮重置停用的陈旧判定，任何东西都永远不会停用。锚点保持为召回的纯函数。

**摘要与蒸馏经验一律进评审。** 整理的每份产物都可以落为 `proposed`。摘要总结的是人已经批准过的行，评审只会每轮重读同样的内容；整理对 `summary` 行拥有权威并自行启用，而所有陈述形态的产物（反思、蒸馏经验）仍留在人审之后。

**自动应用项目蒸馏经验。** 结项项目可以把教训直写组织记忆。共享记忆比项目活得久，并以组织的口吻说话，所以教训和其他共享提案一样进审查队列。

**现在就采用 pgvector 语义去重。** 基于嵌入的相似度能抓住词元 Jaccard 阈值漏掉的转述，代价是整理路径里多一个嵌入存储和模型依赖；该升级继续延期，藏在同一个 `EnterpriseIdentityStore` 接口之后。

## 后果

组织记忆从此收敛：重复塌缩到单一存活者，过期知识自行停用，每个共享分区携带一条当前摘要。复合衰减让未被触碰的记忆以快于半衰曲线的速度淡出——希望记忆长期存活的部署必须召回它，或调高 `halfLifeDays` 与 `retireGraceDays`。定时路径按分区做进程内在途保护，把它启用在多台主机上在构造上不安全；启用定时要求 `service:` 整理行为人加 provider/model 路由，加载时响亮校验。department 目标的反思与经验仍然不可用，因为没有已挂载的服务能解析作者的部门；它们计为失败而不是猜测。重新生成一条管理员已拒绝的摘要会因确定性编号冲突响亮失败，而不是伪装成 `unchanged`。

## Testing

验收链在无 key 环境经公共 API 跑通真实 SQLite 身份仓库：锚定项目的成员会话经 `memory_write` 写入三条教训（近似重复对双双落库，含 email 的一条被共享隐私策略拒绝），项目归档并拒绝后续写入，蒸馏以服务行为人和审计记录把近似重复经验对提入组织审查，管理员批准后，同组织的新无锚定会话在 `[Organization memory]` 下召回两条教训——随后一次整理运行接替重复对、把 30 天龄期条目的固定重要度衰减一半、停用一条低于阈值的过期条目并替换上一条摘要，被接替的重复条目离开召回。包测试覆盖纯规划逻辑、两个存储的血缘与重要度批次支持、运行时各阶段及其结构化跳过与失败记录、蒸馏的结构化跳过、公告抽取及其回落，以及控制器端点。模型可见行为变化的录制会话快照为 owner-local：本环境没有 `DEEPSEEK_API_KEY`，企业组合还需要它的 PostgreSQL 环境，Owner 按 P1 惯例在 key 与企业环境就绪后用 `DSH_SNAPSHOT=record` 录制。

## Deferred

团队与群隔间第三次延期：P3 规格条目只点名共享与项目分区，而群/团队摘要需要本轮未设计的跨运行成员语义。pgvector 升级继续留在存储接口之后。`validFrom` 拿到了列和读取路径，但还没有写入路径。公告接收对已抽取提案与既往已批准行的对账只做到确定性编号跳过，重新公告的事实仍可能以近似重复进入审查队列。
