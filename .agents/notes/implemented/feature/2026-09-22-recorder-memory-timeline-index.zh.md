# Agent Note: 录音记忆时间轴索引

Status: implemented

[English](2026-09-22-recorder-memory-timeline-index.md) | 中文

## Problem

录音入库把每个 ASR 短段表示成一篇知识文档。最近录音查询在应用所有者、时间和主题过滤前会加载全部这类文档。增量加工还会确认未进入模型窗口的段 ID，并为每个微批次新建可搜索文档，包括空结果。历史数量因此同时增加查询工作量和文档碎片，而加工账本可能夸大已完成覆盖。

## Decision

录音 worker 为每个 JSONL 源推进持久字节游标，并在一个 SQLite 连接中保存已解析行。`indexed_v1` 将早期入库确认重放一次到新时间轴，`processed_v2` 按最旧优先的有界窗口重新加工早期账本。成功的加工请求只确认实际位于该请求中的新段 ID。

knowledge 插件拥有独立的录音 SQLite store，以组织、用户和稳定段 ID 为键。B-tree 所有者/时间索引服务时序范围，所有者限定的词元倒排索引排序主题。相邻段共享稳定录音会话。主题查询返回命中、有界相邻证据、会话摘要和活动加工记忆，不读取知识文档。

加工通过稳定 document ID 幂等更新，为每个录音会话保留一篇原文文档和一篇记忆文档。提取记录使用稳定记忆 ID，并保留证据 ID 和输入版本。空提取只在加工表中记录 `no-new-memory`，不创建知识文档。

## Alternatives considered

**保留每段一文档并增加缓存。**缓存仍会留下无界失效和碎片化模型可见结果，因此录音查询改以索引时间轴为事实源。

**原始段使用通用 chunk FTS 索引。**通用索引无法在加载文档元数据前过滤源时间，并会把原始录音保留与知识文档数量耦合。

**时间轴使用 SQLite FTS5 trigram 排序。**新鲜的 10,000 段基准在本机测得约 531 ms 中位数。专用所有者-词元倒排表在同一查询和上下文结果上测得 51.523 ms 中位数与 54.713 ms P95。

## Consequences

原始段在一次索引写入后可查，不再每段增加一篇知识文档。查询成本跟随请求的所有者/时间/主题范围，而不是完整知识语料库。历史 JSONL 可在不删除源数据的情况下重放，会话文档随加工推进而收敛。录音 store 增加一个 SQLite 产物，并使用确定性词法词元化而非通用语义排序；加工记忆和相邻证据提供给数字员工的语义上下文。
