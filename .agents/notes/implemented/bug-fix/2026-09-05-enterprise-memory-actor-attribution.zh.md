# Agent Note：企业记忆执行者归属与策略门控启用

状态：已实现

[English](2026-09-05-enterprise-memory-actor-attribution.md) | 中文

## 问题

企业自动业务记忆采集把 Profile 中静态的 bootstrap 管理员作为提案作者、审核者和审计执行者；同一 Profile 还开启了全组织自动启用。这会错误归属交互式工作，并把不存在的组织决策表现得像人工批准。

## 决策

记忆上下文优先解析已认证请求主体，其次解析持久化企业 Session 所有者绑定。未绑定的后台调用除非 Profile 显式提供已启用、以 `service:` 为前缀的企业身份，否则失败关闭。自动采集默认只创建提案；仅当匹配的组织可见 `enterprise-memory-autonomy` 资源策略包含该执行者且由已启用管理员创建时，才自动启用。资源策略键在全局唯一空间中按组织命名：`<orgId>:organization` 或 `<orgId>:department:<departmentId>`。

个人工作区偏好不进入此共享记忆流程。审计行同时记录解析出的执行者和策略是否启用条目，因此提案不会被误认为已批准。

## 后果

随附企业 Profile 不再将 `bootstrap-admin` 设为自动记忆执行者，也不再通过配置开启组织范围启用。运营者必须先通过已认证企业控制平面主动建立治理策略。既有未绑定自动化需要显式服务身份才可采集记忆。

## 考虑过的替代方案

**继续将自动采集归属为 `bootstrap-admin`。** 不予采纳，因为 bootstrap 账户属于配置，不是实际执行工作的已认证人员或服务；这样会让记忆来源和审计归属都失真。

**使用 Profile 级布尔值启用自动启用。** 不予采纳，因为启用是组织治理决策，必须记录管理员、允许的执行者和范围；静态 Profile 值既无法提供这些事实，也无法避免不同组织的策略发生冲突。
