# Agent Note：已拒绝升级的弹窗循环

状态：已实现

[English](2026-09-12-rejected-escalation-prompt-loop.md) | 中文

## 问题

用户拒绝 `danger-full-access` 沙箱升级后，模型可以在同一轮次用改写后的 justification 再发起一次调用。ApprovalService 会分配新请求 ID 并再次分发，导致用户每次拒绝后仍看到同一高权限弹窗，无法正常继续对话。

## 决策

ApprovalService 只对沙箱升级理由生成窄范围去重键：工具名加请求的目标模式。分发询问前，它扫描当前未结束轮次的持久 `approval/asked` 和 `approval/decided` 事件对。同一键已有拒绝时，新请求直接返回 `rejected`，不再询问人类应答者。服务仍写入新审计事件对，后续轮次则从新的决策范围开始。

## 考虑过的替代方案

**按请求 ID 或 justification 去重。** 模型会创建新调用 ID，也可以改写 justification，两者都不能表示人类已做出的决定。

**一次拒绝后禁用全部审批。** 这会错误抑制无关命令和更窄权限。去重键只限于同一轮次内的一个工具与目标模式。

## 影响

人类拒绝一次后，该升级范围不再反复骚扰，同时保持失败即拒绝和完整审计历史。真正不同的目标与后续轮次仍可以询问。
