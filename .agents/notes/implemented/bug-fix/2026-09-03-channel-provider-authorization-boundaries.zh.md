# Agent Note: 渠道提供方保持各自的授权前置条件与意图授权

Status: implemented

[English](2026-09-03-channel-provider-authorization-boundaries.md) | 中文

## 问题

渠道配置曾把每个已启用企业提供方都当作必须提供租户，但飞书和钉钉官方 OAuth 只需要已配置的应用账号与 Credential。个人微信网站应用 OAuth 也曾看似授予通知和状态意图，但该官方流程只能为经认证接管验证身份，不提供个人聊天投递 API。飞书 code 交换仍指向已被取代的 v2 端点，浏览器则按 JavaScript 字符数而不是 Host 的 2,048 字节上限准入回调 code。

## 决策

只有已启用企业微信配置必须提供非空租户 CorpID。飞书和钉钉可使用账号 ID 与已配置 Credential 启用并开始官方授权；除非用户提供或提供方验证了租户，持久记录不保留租户。

个人微信网站应用授权仅准入 `handoff` 意图。通知、状态、Team 启动、决策响应、入站命令、非公开 iLink 与个人聊天协议均不在这条官方授权路径内。

飞书通过 `https://accounts.feishu.cn/oauth/v3/token` 交换授权 code，使用官方 JSON 请求字段并读取顶层 `access_token`。回调 code 的 UTF-8 编码超过 2,048 字节时，浏览器会在调用 Remote 或发布成功前拒绝它。

## 验证

Kernel 测试固定五种意图决定，以及飞书 v3 的准确 URL、method、JSON 字段与顶层 token 响应。Repository、controller 与工作台测试覆盖无租户的飞书/钉钉启用、无 CorpID 的企业微信拒绝、不伪造租户，以及个人微信仅接管呈现。浏览器回调测试使用少于 2,048 个字符但超过 2,048 个 UTF-8 字节的多字节值。

## 考虑过的替代方案

**为每个企业提供方保留共同租户前置条件。** 拒绝：这会虚构提供方要求，并阻止有效的飞书和钉钉配置。

**把通知和状态保留为不修改状态的个人微信意图。** 拒绝：不修改状态并不会让不受支持的个人聊天传输变成官方或可投递能力。

**先调用飞书 v2，再 fallback 到 v3。** 拒绝：在没有官方兼容要求时，预发布代码库不保留过时提供方端点。

**由 Host 拒绝过大回调 code。** 拒绝：浏览器仍会传递本地可确定拒绝的输入，而且可能在 Remote 失败前发布会误导用户的中间成功行为。

## 后果

提供方配置与各自官方前置条件一致，不再使用共同企业近似条件。个人微信仍可用于身份与经认证接管，不会暗示聊天投递。飞书遵循当前官方 token 交换，client 与 Host 强制同一字节上限。未来个人聊天传输必须另外提供公开协议、adapter 证据、授权策略与持久投递记录。
