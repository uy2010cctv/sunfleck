# Agent Note: 把提供方知识库绑定到数字员工

Status: implemented

[English](2026-09-14-bind-provider-knowledge-to-employees.md) | 中文

## Problem

“能力资产 → 知识”已经嵌入提供方管理界面，但员工编辑仍只读取企业资产目录。提供方知识库因此能增加管理页数量，却不能被数字员工或对话选择。

## Decision

员工编辑器在“知识”分类中拥有 `enterprise.employee-knowledge-bindings` 槽位。知识提供方接收员工 Preset id，渲染自己的知识库选择器，持久化自有引用，并回报已选择数量。企业资产目录继续管理原生版本化资产；提供方文档不复制进入该目录。

对话插件可以向 Session 级 `conversation.input.left` 提供控制。提供方按以下顺序解析有效检索范围：对话显式选择、员工 Preset 绑定、既有全局选择。显式选择空集合时不匹配任何知识库；恢复继承只删除当前对话覆盖。

绑定贡献在能力分类切换期间保持挂载，因此控件隐藏时也能加载已保存数量。原生回退控件只在知识分类激活时渲染。

员工列表与概览通过同一提供方槽位的只读 `summaryOnly` 呈现读取数量。统计来自已保存的员工绑定或可用知识库元数据，与编辑器导航无关。`refreshKey` 触发重新读取，空值区分加载中或不可用数据与确认的零。摘要卸载或请求发生变化后，提供方忽略旧响应。

## Alternatives considered

只挂载选中的分类。未采用，因为数量卡片在所有分类及编辑器重载后都会显示。

## Consequences

提供方绑定跟随稳定的员工 Preset 身份，新对话无需复制文档即可生效。提供方必须对自动检索和模型可见知识工具执行同一有效范围。员工草稿发布与原生资产版本管理仍是独立操作。

## Verification

工作台测试覆盖选择知识分类前加载已保存数量、切换分类保持贡献挂载，以及发布式重载和切换员工时更新数量。提供方测试覆盖员工/对话映射持久化、优先级、显式空范围、UI 注册和对话范围自动检索。
