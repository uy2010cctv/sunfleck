# Agent Note: 员工能力绑定可见性

Status: implemented

[English](2026-09-14-visible-employee-capability-bindings.md) | 中文

## Problem

员工编辑器在分类卡片中统计已有绑定，却从选择器排除这些资产，仅在只读 JSON 中展示引用。当员工已经绑定全部可用资产时，界面看起来无法选择任何能力；空分类与目录加载失败也无法区分。

## Decision

编辑器按分类展示已绑定名称与固定修订，保留当前目录资产的可选状态并明确标注已绑定，禁止重复添加。更新资产时替换相同类型与资产 ID 的旧引用；移除单行时保留其他绑定。已归档或目录中不存在的资产仍通过已有引用展示，不会直接消失。

分类数字表示绑定数量。加载中、权限或加载失败、没有可用资产、全部资产已绑定分别展示。知识分类为空，不表示其他企业记忆或提供方知识可以直接作为资产绑定。

所有修改使用既有的本地草稿更新操作。保存与发布仍需显式执行；查看或选择资产不会改变员工已持久化的能力。更广泛的员工工作台与自主学习机制保持不变。

## Alternatives considered

**继续隐藏已绑定资产。** 可以防止重复添加，但用户无法在主要编辑界面管理已有能力。

**自动绑定首项资产或转换其他知识记录。** 这会在没有明确选择资产时授予能力，并混淆各自独立拥有的数据。

## Consequences

能力调整仍是需显式保存的草稿中的版本化资产引用。编辑器不会将 Workspace 插件清单或企业记忆记录转换成员工绑定。

## Verification

组件测试覆盖仅选择已绑定项不写入、移除时保留其他分类、替换修订，以及空目录与加载失败的区别。渲染内联快照固定选项标签和绑定行；既有结构化添加与分类切换测试继续保留在同一测试集。
